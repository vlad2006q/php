## 1. Цель работы

Целью проекта является разработка серверного веб-приложения на чистом PHP для просмотра электронного каталога книг. Проект закрепляет работу с массивами, функциями, GET- и POST-запросами, сессиями, JSON-файлами, серверной валидацией и безопасным HTML-выводом.

## 2. Постановка задачи

Необходимо создать каталог, в котором посетитель может искать книги по названию, автору и описанию, фильтровать результаты по жанру и году издания, сортировать список и сохранять выбранные книги в избранном. По условию темы данные хранятся в JSON, а избранное — в сессии. Для изменяющих операций требуется POST и CSRF-защита.

## 3. Используемые технологии

- PHP 8.4+: серверная логика, типизированные функции, обработка запросов.
- HTML5: структура страниц и формы.
- CSS3: адаптивный интерфейс.
- JSON: хранение демонстрационного каталога в `var/data/books.json`.
- PHP Sessions: список избранного и CSRF-токен.
- Git и GitHub: контроль версий и публикация исходного кода.

## 4. Структура приложения

Публичная директория `public` содержит страницы каталога, карточки книги, избранного и POST-обработчик избранного. В `src` находятся общие функции и настройка сессии. Каталог книг расположен в `var/data`, вне публичной директории. Тестовые сценарии и документация вынесены в отдельные каталоги.

## 5. Структура данных

Каждая книга представлена JSON-объектом с полями `id`, `title`, `author`, `genre`, `year` и `description`. Поле `id` служит уникальным идентификатором книги. При чтении файла используется `json_decode()` с флагом `JSON_THROW_ON_ERROR`, что позволяет контролируемо обрабатывать повреждённый JSON.

## 6. Реализованная функциональность

1. Просмотр каталога из 30 демонстрационных записей.
2. Поиск по названию, автору и описанию без учёта регистра.
3. Фильтрация по жанру и году издания.
4. Сортировка по названию и году.
5. Просмотр отдельной карточки книги.
6. Добавление и удаление книг из избранного.
7. Сохранение избранного в сессии текущего браузера.
8. Сообщения для пустого результата и несуществующей книги.

## 7. Обработка запросов

Параметры поиска, фильтров и сортировки передаются методом GET, потому что они не изменяют состояние приложения. Добавление и удаление избранного выполняются методом POST. После успешной обработки выполняется перенаправление с кодом 303, что снижает риск повторной отправки формы при обновлении страницы.

## 8. Безопасность

Перед выводом динамических значений применяется `htmlspecialchars()` с флагами `ENT_QUOTES` и `ENT_SUBSTITUTE`. Значение ID проверяется на допустимый числовой формат, а книга ищется в исходном каталоге. Для изменения избранного проверяется CSRF-токен через `hash_equals()`. Сессионная cookie имеет параметры `HttpOnly` и `SameSite=Lax`; флаг `Secure` включается при HTTPS. Секретные данные проекту не требуются.

## 9. Тестирование

Подготовлены сценарии обычного поиска, фильтрации, сортировки, пустого результата, просмотра карточки, добавления и удаления избранного, неверного CSRF-токена, неподдерживаемого метода и несуществующего ID. Дополнительно описаны проверки XSS-ввода и граничных значений. Перед сдачей следует выполнить сценарии в собственном окружении и вставить скриншоты фактического результата.

## 10. Инструкция запуска

Требуется PHP 8.4+ с расширениями `json`, `session` и `mbstring`. В корне проекта выполняется команда `php -S localhost:8000 -t public`. После запуска приложение доступно по адресу `http://localhost:8000`. Для остановки сервера используется `Ctrl+C` в терминале.

## 11. Ограничения и развитие

В текущей версии отсутствует административное управление книгами, авторизация и база данных. Избранное связано с текущей сессией и не синхронизируется между устройствами. В дальнейшем можно добавить административную форму с валидацией, журнал выдачи книг, пагинацию и авторизацию.

## 12. Заключение

В рамках мини-проекта разработана основа электронного каталога библиотеки на чистом PHP. Приложение использует JSON для хранения данных, сессии для избранного, GET для фильтрации и POST с CSRF-токеном для изменения состояния. Проект демонстрирует применение основных тем лекций 1–8. Перед защитой необходимо заполнить данные автора, проверить приложение и добавить собственные скриншоты.
